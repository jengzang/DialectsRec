# 随机采集顺序

用户要求：录音随机，首页查看完整进度维持句库固定顺序。用户已授权直接执行方案，无需再次确认。

## 决策

- 创建采集任务时，对已选类别和句号范围内的句子做一次等概率洗牌，不重复、不遗漏。各次新建任务使用新的随机源，不依赖固定的用户 ID 哈希。
- 每次进入重新洗牌会让上一句和断点失效；数据库全局随机查询会影响进度展示。因此仅在内存任务队列洗牌，并持久化完整 sentence_id 顺序。
- 队列、当前位置、筛选条件和发音人/句库身份在同一个 SQLite 事务内保存。重启、返回、权限请求后恢复原顺序；新建任务才重新随机。
- 旧版本任务首次恢复时保留已浏览的前缀和当前句，仅随机打乱后续句子；不改已保存录音、完成/跳过状态或原始 sentence_id。
- 已保存队列必须与当前筛选内句子一一匹配。身份不符、重复 ID、丢失 ID、未知 ID 时提示重新选任务，避免用旧位置对应到错误句子。
- 进度页、分类浏览、导出继续使用现有 `ORDER BY order_index`，不改数据库句库顺序和数据格式。
- 任务选择说明提示随机顺序，录音页展示“随机采集”及队列位置，句子信息仍展示原句号。
- 版本升至 versionCode 6 / versionName 1.5，安装包名 `方言语音采集-1.5.apk`。

## 验证

Java 单测检查完整排列、不同随机源、不可变输入、序列化恢复、非法队列、旧任务迁移、空/单句/筛选边界及固定浏览顺序。模拟器检查升级恢复、新建随机队列、前后导航、重启断点、保存/跳过对应句号和进度列表固定排序。执行 Python 测试、Android 单测、lint 和打包。

## 实际导出回归发现的附加修复

实际 ZIP 校验发现旧实现未保存句库的 notes/length_bucket 元数据，导致内置 corpus_hash 与导出内容不符。数据库升级至 schema 4，保存这两个原有协议字段；旧数据库仅为完全匹配内置 ID、文本、分类和难度的记录补回资产中的元数据，不修改提示正文、采集记录、进度或队列。导入、哈希计算和导出均保留元数据。协议和句库版本不变，因为这是恢复原有句库元数据。
